# دفترچه راهنمای NEXUS — ساده و قدم‌به‌قدم

این فایل برای خودت است، کنار برنامه. (مستندات خود پروژه انگلیسی است.)

---

## ۱. NEXUS به چه درد می‌خورد؟

فرض کن یک سایت داری که کاربر ثبت‌نام می‌کند و سایت یک **کد تأیید** به ایمیلش می‌فرستد.
می‌خواهی مطمئن شوی این مسیر هنوز کار می‌کند. NEXUS این کار را خودکار انجام می‌دهد:

> ثبت‌نام می‌کند → ایمیل را می‌گیرد → کد را درمی‌آورد → کد را وارد می‌کند → می‌گوید موفق شد یا نه.

ایمیل واقعی هم لازم نیست: صندوق‌های ساختگی روی دامنهٔ `example.test` می‌سازد که هیچ‌جا نمی‌رود.

**دو تکه دارد که هر دو باید روشن باشند:**

1. **بک‌اند** (سرور) — در یک پنجرهٔ PowerShell.
2. **برنامهٔ دسکتاپ** (همین `NEXUS.exe`) — پنجره‌ای که می‌بینی.

## ۳. روشن کردن — سه قدم

### قدم ۱: بک‌اند را روشن کن

یک پنجرهٔ **PowerShell** باز کن و این‌ها را یکی‌یکی بزن:

```powershell
cd C:\Users\parsa\Documents\deepseek-harness\default-workspace\NEXUS\backend

$env:NEXUS_SECRET_KEY="یک-رشته-تصادفی-حداقل-۳۲-کاراکتر"
$env:NEXUS_API_KEY="یک-کلید-تصادفی-حداقل-۱۶-کاراکتر"
$env:NEXUS_PROXY_CREDENTIAL_KEY="یک-رشته-تصادفی-دیگر"
$env:NEXUS_DATABASE__URL="sqlite+aiosqlite:///./nexus.db"

uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**این پنجره را نبند.** تا وقتی باز است، سرور کار می‌کند.
اگر همه‌چیز درست باشد، آخرین خط چیزی شبیه `Uvicorn running on http://127.0.0.1:8000` است.

> بار اول اگر دیتابیس نداری، قبلش این را بزن: `uv run alembic upgrade head`

### قدم ۲: کلید را به برنامه بده

در یک پنجرهٔ PowerShell **دیگر** (این هم باید open بماند):

```powershell
$env:NEXUS_DESKTOP_API_URL="http://127.0.0.1:8000"
$env:NEXUS_DESKTOP_API_KEY="همان-کلیدی-که-در-قدم-۱-گذاشتی"

C:\Users\parsa\NEXUS-App\NEXUS.exe
```

**راه ساده‌تر:** روی فایل `START-NEXUS.cmd` (کنار همین راهنما) دوبار کلیک کن.
اگر آن را باز کنی و کلید را داخلش بگذاری، دیگر هر بار لازم نیست چیزی تایپ کنی.

### قدم ۳: (فقط برای تست ثبت‌نام) سایت آزمایشی را روشن کن

```powershell
cd C:\Users\parsa\Documents\deepseek-harness\default-workspace\NEXUS\backend
uv run python -m demo_target.run
```

یک سایت واقعی روی `127.0.0.1:9000` بالا می‌آید که NEXUS روی آن ثبت‌نام تست می‌کند.
برای کار با پروکسی‌ها و ایمیل‌ها این قدم لازم نیست.

## ۴. صفحه‌ها — هر کدام چه کار می‌کند

از نوار سمت چپ:

| صفحه | به زبان ساده |
|---|---|
| **Dashboard** | نگاه کلی: چند پروکسی سالم، چند صندوق ایمیل، چند job. |
| **Proxy Manager** | لیست پروکسی‌ها. `Import…` لیست اضافه می‌کند، `Check unknown` سلامتشان را تست می‌کند. |
| **Email Manager** | صندوق‌های ایمیل ساختگی. `New inbox` صندوق می‌سازد، `Poll selected` ایمیل‌های تازه را می‌آورد. |
| **Registration Lab** | مهم‌ترین صفحه. هدف تست را ثبت می‌کنی، بعد `New campaign…` یک تست ثبت‌نام اجرا می‌کند. |
| **Task Monitor** | کارهای در حال اجرا. پیشرفت و لاگ. دکمهٔ `Cancel job` متوقفش می‌کند. |
| **Settings** | فقط نمایش: سرور کجاست، چه محدودیت‌هایی فعال است. |
| **Logs** | کارهایی که خودِ برنامه انجام داده و خطاها. |

## ۵. یک تست واقعی در ۶۰ ثانیه

1. قدم ۱ و ۳ را انجام بده (بک‌اند + سایت آزمایشی).
2. برنامه را باز کن (قدم ۲).
3. برو به **Registration Lab**.
4. دکمهٔ **Add bundled demo target** را بزن. (هدف تست ثبت می‌شود.)
5. روی همان ردیف هدف کلیک کن تا انتخاب شود.
6. **New campaign…** → تعداد را بگذار `3` → OK.
7. برو به **Task Monitor** و ببین پیشرفت می‌کند.
8. برگرد به **Registration Lab**، روی کمپین کلیک کن → جدول نتایج می‌آید.

اگر ستون **Outcome** نوشته باشد `success` و **Account** نوشته باشد `active`، همه‌چیز درست کار کرده است.

## ۶. اگر خطا دیدی

| چه می‌بینی | معنی | چه کار کن |
|---|---|---|
| `Could not reach the NEXUS API` | بک‌اند روشن نیست | قدم ۱ را چک کن؛ آن پنجره بسته نشده باشد |
| `401 unauthenticated` | کلید اشتباه است | کلید برنامه باید **عیناً** همان `NEXUS_API_KEY` باشد |
| `403 target_not_authorized` | هدف مجاز نیست یا یادداشت مجوز ندارد | در Registration Lab هدف را انتخاب کن و `Authorize selected…` بزن |
| `403 ssrf_blocked` | آدرس خصوصی مسدود است | برای تست محلی: `$env:NEXUS_NETWORK__ALLOW_PRIVATE_TARGETS="true"` (فقط روی سیستم خودت) |
| هیچ ایمیل نمی‌آید | سایت آزمایشی روشن نیست | قدم ۳ |
| `stopped_by_target` | خودِ هدف گفت «زیاد تلاش کردی» یا CAPTCHA خواست | این **درست** است؛ NEXUS دور نمی‌زند. بعداً دوباره امتحان کن |
| پنجره باز می‌شود ولی خالی است | بک‌اند جواب نمی‌دهد | صفحهٔ **Logs** را ببین |

## ۷. چیزهایی که NEXUS عمداً انجام نمی‌دهد

اگر انتظار یکی از این‌ها را داری، این برنامه ابزار درستی نیست:

- ساخت اکانت جیمیل/اوت‌لوک یا هر ایمیل واقعی.
- رد کردن CAPTCHA، دور زدن محدودیت نرخ، یا پنهان کردن ترافیک با پروکسی.
- تست روی سایت‌هایی که مالکشان نیستی یا مجوز کتبی نداری.

اگر هدفی ۴۲۹ یا CAPTCHA بدهد، NEXUS **می‌ایستد** و گزارش می‌دهد — چون کارش تست سالمِ محصول است، نه دور زدن محافظتش.

## ۸. خاموش کردن

- پنجرهٔ برنامه را ببند.
- در پنجرهٔ بک‌اند `Ctrl+C` بزن.

داده‌ها در فایل `backend\nexus.db` می‌مانند. اگر خواستی از صفر شروع کنی، آن فایل را پاک کن و
دوباره `uv run alembic upgrade head` بزن.

## ۹. کلیدها را کجا بسازم؟

هر کدام از این‌ها را یک بار اجرا کن و خروجی را کپی کن:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

سه‌تا بساز: یکی `NEXUS_SECRET_KEY`، یکی `NEXUS_API_KEY`، یکی `NEXUS_PROXY_CREDENTIAL_KEY`.

⚠️ کلیدی که در این راهنما یا در جلسهٔ تست استفاده شد **فقط برای تست محلی** بود. برای استفادهٔ
واقعی کلید تازه بساز و جایی که امن است نگه دار (نه داخل گیت).
